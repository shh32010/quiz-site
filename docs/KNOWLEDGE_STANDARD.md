# 知识点讲义内容与展示标准（KNOWLEDGE_STANDARD）

> **地位**：知识点讲义唯一的内容与展示标准。新写、重写、审核、验收都以本文为准。
> **取代**：`docs/project/KNOWLEDGE_REFACTOR.md` 第 2.2、2.3 节里的内容约束（“核心 ≤20%”“与 PDF 连续重合率 <15%”“蓝色=重点”），以及 2026-11-09 审计报告里提出的“统一质量线”。
> **制定**：2026-11-10

---

## 1. 范围与原则

1. **唯一内容**：前端知识点页面只展示一份内容，即按考纲三级节点组织的结构化讲义（`kb_entry` / `kb_revision`）。旧知识点卡片不再展示，见第 6 节。
2. **PDF 全覆盖**：两本复习教程 PDF 里的每一条知识内容、每一张表、每一张导图、每一段代码、每一处颜色标记，都必须在对应讲义中出现，**不允许遗漏**。
3. **标记一一对应**：讲义里的重要度标记必须和 PDF 颜色完全对应。PDF 有标记的地方必须有，PDF 没有标记的地方不得自行添加。
4. **原文与标记 100% 保真**：两本 PDF 为公开复习资料，无版权顾虑。原文知识表述、术语、数字、公式、单位、代码、命令、表格数据直接保真提取并按结构化块（段落/列表/表格/代码/树/配图）排版，**不缩写、不删减、不改写原意**。
5. **配图与导图全保留**：过滤跨页重复的水印/底纹图（`xref` 出现次数 `>2`）与全部 1-bit（`bpc == 1`）半色调蒙版水印，合并被水平切片的条带图与并排对比图后，按页面正向裁剪渲染（`page.get_pixmap(clip=..., dpi=200)`，杜绝 DIB 负 Y 缩放导致的图片倒置，并将操作篇 p175 旋转大图逆时针旋转 90° 还原正向），将 PDF 中的正文有效配图（理论篇 131 张、操作篇 300 张，共 431 张，含硬件结构图、纯矢量拓扑图、UML 图、操作界面图等）与矢量导图全部提取保留（导图优先转可折叠 `tree` 或保真静态图 `img` 块）。

## 3. 颜色标记规范

### 3.1 PDF 颜色 → 讲义标记

| PDF 颜色（图例原文） | 文字色值（容差 ±40） | 讲义行内语法 | 前端显示 | 含义 |
| :--- | :--- | :--- | :--- | :--- |
| 红色：核心高频（必需熟记） | `#FF0000`、`#C00000`（非代码字体时） | `==文本==` | 红色底纹 + 「核心」 | 核心 |
| 绿色：重点内容（必需熟悉） | `#00B050` | `^^文本^^` | 绿色下划线 + 「重点」 | 重点 |
| 黄色：难点内容（尽量掌握） | `#FFC000` | `@@文本@@` | 琥珀色底纹 + 「难点」 | 难点 |
| 黑色：常规内容（必需了解） | `#000000`、`#0D0D0D`、`#121212`、`#333333`、`#444444` | 无标记 | 普通正文 | 了解 |
| 蓝等：代码关键字等相关内容 | `#0000FF`、`#A31515`、`#538135`，以及代码字体里的 `#C00000` | `` `代码` `` 或代码块 | 等宽代码 | **代码配色，不是重要度** |
| 图内文字 | `#0563C1` | 写进对应的树块 / 表格 | — | 导图、示意图里的标签 |

> [!IMPORTANT]
> - 旧提取脚本 `extract_pdf_sections.py` 把**蓝色**当成重点，**绿色和黄色都没有识别**。所以现有讲义缺少全部绿色（理论篇约占 13%）和黄色（约占 2.6%）标记，需要按本标准重新提取。
> - 本标准**不使用 `**加粗**`** 来表示重要度。旧讲义里的 `**...**` 重写时一律按 PDF 实际颜色改成对应标记，或者去掉。

### 3.2 标记规则

1. **片段级对应**：PDF 中每一个有颜色的片段（同色、连续的文字）都要以对应语法出现在讲义里。相邻的同色片段可以合并成一个标记。
2. **不得自行加标**：讲义中的每个 `==`、`^^`、`@@` 标记，都必须能在 PDF 里找到同色原文。补充内容一律不加标记。
3. **标记内容**：标记内可以出现 `=`、空格和行内代码；不能嵌套另一种颜色标记；不能跨越表格单元格或列表项。
4. **标题不重复计入**：PDF 中字号 ≥13.6pt 的章节标题即使有颜色，也只作为讲义的块标题，不算正文标记。

### 3.3 块级重要度（自动计算，不手写）

块的 `imp` 字段由发布脚本根据块内标记自动计算：

| 块内包含 | `imp` | 徽标 |
| :--- | :--- | :--- |
| 至少一个 `==红==` | `core` | 核心 |
| 没有红，至少一个 `^^绿^^` | `important` | 重点 |
| 只有 `@@黄@@` | `hard` | 难点 |
| 没有任何标记 | `normal` | 无 |

前端不再提供“只看核心”筛选按钮；`imp=core` 仍表示红色核心块，页面正常展示全部内容。

## 4. 讲义结构规范

### 4.1 组织单元
- **一个考纲三级节点 = 一篇讲义**，共 232 篇。`title` 与考纲名称一字不差。
- PDF 段落到三级节点的映射写在 `private/kb_pipeline/mapping/{theory,skill}.json` 中：一段 PDF 内容**只能映射到一个节点**；任何非排除内容都不能处于未映射状态。
- 讲义块的顺序跟随 PDF 原文顺序。

### 4.2 块类型与字段

| `t` | 必填字段 | 用途 | 规则 |
| :--- | :--- | :--- | :--- |
| `p` | `text` | 段落 | 不得含换行符；多条要点改用 `list` |
| `list` | `items[]`，可选 `ordered` | 要点、步骤 | 每项一条信息；操作截图改写成有序步骤 |
| `table` | `headers[]`、`rows[][]` | PDF 表格、对比 | **PDF 每张表都要转成表格块，行、列、数据不减**；每行列数等于表头列数；单元格不得含 `<br>` 或换行，需要分行时拆成多行 |
| `code` | `lang`、`code` | 代码、命令、配置 | C 代码必须通过 `gcc -fsyntax-only`（片段可补最小上下文）；代码内不使用任何行内标记 |
| `tree` | `root{label, children[]}` | 思维导图、层级图 | PDF 导图的**节点一个不少**，层级深度不限（渲染器需支持递归） |
| `img` | `src`、可选 `alt`/`caption`/`w`/`h` | PDF 正文有效配图 | 清除 `bpc == 1` 水印并合并切片后按页面正向裁剪渲染为 PNG 存入静态目录并登记 `kb_asset`，支持点击灯箱放大 |
| `callout` | `kind`（`trap`/`warn`/`tip`）、`text` | 易错点、注意事项 | 只用于 PDF 中原有的“注意 / 易错 / 提示”类内容，或补充的真题易错点 |

通用字段：`id`（`[a-z0-9-]+`，同一篇内唯一）、`title`（可选，PDF 小标题）、`imp`（自动计算）。不允许出现未定义的字段名，也不允许出现未定义的 `imp` 取值（例如 `key`）。

### 4.3 `source_ref`

```json
{"pdf": "理论复习.pdf", "pages": [12, 13], "spans": 87, "extra": ["题库补充：xxx"]}
```

`spans` 记录本篇讲义覆盖的 PDF 有色片段数，用于自动核对。

## 5. 行内语法与渲染

| 语法 | 渲染 | 说明 |
| :--- | :--- | :--- |
| `` `x` `` | `<code>` | **最先处理**，代码内的 `==`、`*` 等符号原样显示 |
| `==x==` | 核心（红） | 标记内允许出现 `=` |
| `^^x^^` | 重点（绿） | |
| `@@x@@` | 难点（黄） | |

- 正文统一按纯文本转义，**不支持任何 HTML 标签**。
- 渲染后不允许残留裸的 `==`、`^^`、`@@` 符号（自动校验）。
- 页面顶部固定显示图例：核心 / 重点 / 难点 / 了解，和 PDF 图例保持一致。

## 6. 前端统一新版样式与题目关联全面切换

### 6.1 保留现有结构化讲义样式，移除旧卡片视图
保留并统一使用现有的新版结构化讲义样式（`KnowledgeBlockRenderer.vue` + `section/[id].vue`），补齐 `^^重点^^`（绿色）与 `@@难点@@`（黄色）行内标记、`img` 配图块渲染以及多层 `tree` 递归渲染：
| 现状 | 处理 |
| :--- | :--- |
| 节页面的旧卡片轨道（`?legacy=1`、「查看旧版卡片」按钮、旧卡片渲染与目录逻辑） | 删除，统一只渲染新版结构化讲义 |
| `pages/knowledge/outline-preview.vue`（S1-1 试点预览页） | 删除 |
| `/knowledge/kp/:id`、`/knowledge?kp=` 旧深链 | 保留兼容重定向，统一 302 跳转到对应三级讲义锚点 `#group-{nodeId}` |
| 知识点搜索（`GET /api/knowledge/search`） | 切换为检索 `kb_revision.search_text`，搜索结果直接定位到三级讲义节点并带 `?hl=` 高亮 |
| 课程与大纲目录树角标（`GET /api/knowledge/tree`） | 统计各节点下已发布讲义的内容块数（或关联题数），不再统计旧卡片数 |

### 6.2 题目关联全部切换到新版（淘汰旧卡片关联展示）
所有原先查询 `t_knowledge_point` / `t_question_kp` 的业务接口，全面切换为关联 **考纲三级讲义节点（`t_chapter` + `kb_entry`）**：
| 业务场景 | 切换后行为 |
| :--- | :--- |
| **刷题页解析下方「相关知识点」**（`GET /api/questions/{id}/knowledge`） | 直接返回该题所属的考纲三级讲义节点（`nodeId, nodeCode, nodeName`），点击直接跳转到 `/knowledge/section/{parentId}#group-{nodeId}` |
| **学习报告页「薄弱知识点」**（`GET /api/report`） | 按用户在各三级考纲讲义节点下的答题正确率排行，点击直接跳到对应讲义复习 |
| **错题本 / 收藏夹 / 练习历史** | 每道题展示所属三级考纲讲义编号与名称 |
| **报错弹窗「同类题推荐」** | 按同属一个三级考纲节点且同题型匹配 |

### 6.3 旧版卡片处置：合并补充或清理归档
1. **PDF 未覆盖但属于考纲的有效旧卡片考点**：作为补充块（普通文本，不加原书颜色标记）合并进对应三级节点的讲义末尾。
2. **已被 PDF 讲义覆盖或考纲外的旧卡片（如 423 张 Office 操作卡片）**：先备份再软删归档，前后端不再读取展示。

## 8. 发布与回滚

1. 每次发布都生成新的 `rev_no`，旧版本保留，发生问题时把 `kb_entry.published_rev` 指回旧版本即可回滚。
2. 改线上数据前先建备份表（`*_backup_YYYYMMDD`）；含中文的 SQL 一律写成 UTF-8 文件，`scp` 上传后用 `psql -f` 执行。
3. 发布后执行 `redis-cli FLUSHDB`；如有用户能感知的变化，同步更新站内公告。
